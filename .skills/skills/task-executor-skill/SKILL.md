# 作業指示オーケストレータースキル

ユーザーの作業指示を受け取り、デフォルト設定で不足情報を補完しながら、
成果物の完成まで全自動で実行するスキル。

## 最初に読むもの

このスキルのディレクトリを `SKILL_DIR` として:

1. `{SKILL_DIR}/user-defaults.md` — ユーザーのデフォルト設定（出力形式、文体、素材の場所など）

**user-defaults.mdの読み込みが完了してから、Phase 1に進むこと。**

---

## 設計思想

このスキルの目的は「指示を出したら、あとは全部AIがやる」を実現すること。

人間がAIに作業指示を出すとき、指示文には往々にして以下の5項目が欠落している:

1. **成果物の出力形式** — .docxなのか.pptxなのかSlack投稿なのか
2. **提出先・文体** — 社内向けカジュアルか、顧客向け敬語か
3. **インプット素材の場所** — Notionか、ローカルファイルか、Slackか
4. **品質基準** — 言語、文字数、トーンなど
5. **使用可能ツール** — Web検索OK？外部投稿OK？

このスキルでは、これらの不足情報を `user-defaults.md` に事前設定しておくことで、
実行時に質問を挟まず全自動で走りきれるようにしている。

指示文で明示されている項目はそちらを優先し、明示されていない項目のみデフォルト値で補完する。

---

## 処理フロー

### Phase 1: 指示文の構造化解析

ユーザーの指示文から、以下の5項目を抽出する。

| # | 項目 | 抽出例 |
|---|---|---|
| 1 | 成果物の出力形式 | 「スライドにして」→ .pptx |
| 2 | 提出先・文体 | 「クライアント向けに」→ フォーマル敬語 |
| 3 | インプット素材 | 「この議事録から」→ 貼付テキスト or ファイルパス |
| 4 | 品質基準 | 「A4で2枚以内」→ 文字数・ページ数制約 |
| 5 | 使用可能ツール | 「Slackにも投稿して」→ Slack投稿OK |

**抽出ルール:**
- 指示文で明示されている → その値を使う
- 指示文にない → `user-defaults.md` のデフォルト値を使う
- 指示文にもデフォルトにもない → 安全側のフォールバック値を使う

**フォールバック値（最終手段）:**
- 出力形式: .md（マークダウンファイル）
- 文体: ですます調
- 素材: 指示文のテキストのみ
- 品質: 日本語、特に制約なし
- ツール: ファイル生成のみ（外部投稿しない）

---

### Phase 2: インプット素材の収集

Phase 1で特定した「インプット素材の場所」に基づいて情報を集める。

#### 素材の取得方法

| 素材の場所 | 取得方法 |
|---|---|
| 指示文に貼付済み | そのまま使う |
| ローカルファイル | Readツールで読み取る |
| Notion | notionApi MCPで取得 |
| Web上の情報 | WebSearch / WebFetch で取得 |
| Slack | Claude in Chromeでブラウザ操作 |
| その他の外部サービス | まずMCP registryを検索 → なければChrome操作 |

#### 外部サービスへのアクセス判断

外部サービスから情報を取得する必要がある場合、以下の順で試みる:

1. **MCP Connectorの確認**: `search_mcp_registry`で該当サービスのconnectorを検索
2. **接続済みMCPがある** → API経由でアクセス（高速・安定）
3. **MCPがない** → Claude in Chromeでブラウザ操作（フォールバック）

この判断は素材の収集だけでなく、Phase 4の成果物の納品（Slack投稿、メール送信など）にも適用する。

---

### Phase 3: 成果物の作成

Phase 1で決定した出力形式に基づいて、適切な方法で成果物を作成する。

#### 専門スキルへの委譲

ファイル作成が必要な場合、対応する専門スキルのSKILL.mdを読み込んで、その指示に従う。
これは成果物の品質を最大化するために重要なステップ。

| 出力形式 | 委譲先スキル | 読み込むファイル |
|---|---|---|
| .docx | docx | docxスキルのSKILL.md |
| .pptx | pptx | pptxスキルのSKILL.md |
| .xlsx | xlsx | xlsxスキルのSKILL.md |
| .pdf | pdf | pdfスキルのSKILL.md |
| .md / テキスト | なし（直接作成） | — |
| Slack投稿 | なし（Phase 4で処理） | — |
| メール | なし（Phase 4で処理） | — |

専門スキルに委譲する場合、Phase 1で決定した品質基準（文体、文字数、言語など）を
スキルの指示に追加情報として渡すこと。

#### 直接作成の場合

専門スキルがない形式（.md、テキスト、コードなど）は、
Phase 2で収集した素材とPhase 1の品質基準に基づいて直接作成する。

---

### Phase 4: 成果物の納品

作成した成果物を、指定された方法で納品する。

#### ファイル保存（デフォルト）

成果物がファイルの場合、ワークスペースフォルダに保存し、computer://リンクで提示する。

#### 外部サービスへの投稿

`user-defaults.md` の「使用可能ツール」でOKとされている場合のみ実行する。
デフォルトが「外部投稿NG」の場合、ファイルとして保存するだけに留める。

外部投稿の実行方法は、Phase 2と同じルーティング（MCP優先 → Chrome操作フォールバック）を使う。

| 納品先 | 方法 |
|---|---|
| Slack | MCP or Chrome操作 |
| Gmail | MCP or Chrome操作 |
| Notion | notionApi MCP |
| その他 | MCP検索 → Chrome操作 |

---

### Phase 5: 完了報告

処理が完了したら、以下を簡潔に報告する:

- 作成した成果物（ファイルリンク）
- 実行した外部操作（あれば）
- 指示文から推測した項目があれば、何をどう補完したかを一行で付記

報告は簡潔にすること。長い説明は不要。
